## 三、gateway-go（Go 接入网关）

### 功能点

1. 网关启动入口与路由装配
2. 访问日志中间件（请求审计）
3. 令牌桶限流（按客户端 IP，M5-5.5 增租户维度：大租户独立配额 + 空闲条目清扫）
4. **JWT 鉴权与可信租户上下文（M5-5.5：HS256 校验，密钥环境变量，租户注入）**
5. 健康检查接口
6. gRPC 契约代码（gen-proto.sh 生成）
7. gRPC 客户端封装（网关 → Java 域 ping 链路）
8. **WSS 长连接网关（M2-A3）**：连接管理、心跳 ping/pong、断连缓冲（环形 200 条）+ seq 续传、消息路由
9. **会话域 gRPC 客户端（M2）**：建会话/发消息/拉取续传，5s 超时
10. **用户端建会话接口（M2）**：`POST /api/v1/session` 转发 Java 会话域
11. **坐席回复下行接口（M2）**：`POST /api/v1/agent/reply` 落库 Java 后广播下行
12. **实时链路集成测试（M2-A5）**：用户↔网关↔Java 全链路闭环验证
13. **客服工作台接口（M2-B5）**：`GET /api/v1/agent/queue` 客服队列、`POST /api/v1/agent/takeover` 接管抢单、`GET /api/v1/agent/sessions` 坐席会话列表
14. **工单域接口（M2-B5）**：`POST/GET /api/v1/agent/tickets` 建单/列表、`POST /api/v1/agent/tickets/:id/status` 状态流转
15. **AI 流式片段推送（M3-3.8）**：`chunk` 下行信封（`index`/`finished` 显式下发，前端据此打字机与收尾）、Kafka 片段消费者（`lingxi.ai.chunk` → Hub 广播至会话连接，单条消息失败不中断循环、ctx 取消优雅退出）、`GATEWAY_KAFKA_*` 开关与地址配置（默认关闭，本地无 Kafka 也能启动）
16. **编排 Studio 接口（M4-4.7）**：`/api/v1/studio/workflows` 九条路由——列表、新建、详情、保存草稿（`PUT .../draft`，请求体直接承载画布图对象，Go 原样转 JSON 文本上送）、发布、版本列表、版本详情、回滚、删除；gRPC 编排域客户端（复用 Java 同一地址，5s 超时）；参数缺失/非法 400、通道故障 503、业务拒绝以 `{ok:false, reason}` 返回（与工单域约定一致）
17. **灰度发布与分流接口（M4-4.8）**：新增 `POST /api/v1/studio/workflows/:id/rollout`（网关只做范围校验：`canary_percent ∈ [0,100]`、开启灰度必须带 `canary_version`，业务规则收敛到 Java）；发布接口增 `canary` 开关（灰度发布）；`workflowView` 增 `canary_version`/`canary_percent` 并随列表/详情下发；客户端新增 `Rollout`、`PublishWorkflow` 增 `canary` 参数
18. **运营报表与满意度接口（M5-5.1）**：新增报表域 gRPC 客户端（`GetFunnelReport`/`GetTokenReport`/`GetCsatReport`，复用 Java 同一地址，5s 超时）；新增四条路由——`GET /api/v1/reports/funnel|tokens|csat`（`tenant_id` 必填、`from`/`to` 为可选 epoch 毫秒且须非负；缺参/非法/区间反置 → 400，gRPC 失败 → 503；`from`/`to` 缺省交由 Java 报表域套用最近 7 天）+ `POST /api/v1/session/:session_id/feedback`（评分越界 → 400，业务拒绝以 `{ok:false, reason}` 返回）；Token 报表的「估算条数合计」由 Go 视图层按明细行汇总（协议未单列该字段）
19. **建会话租户注入（M5-5.1 联调补齐）**：`POST /api/v1/session` 请求体新增**可选** `tenant_id`，缺省回落网关默认租户 `GATEWAY_DEFAULT_TENANT`（默认 `lingxi`）——网关作为接入层唯一的租户注入点（生产由鉴权中间件按 JWT 注入，本地联调走默认租户），会话及其后续全部事件（用户消息 / 埋点 / 接管）据此归属租户。**此前建会话未携带租户，导致 Java 侧会话租户为空字符串，分析报表按租户查询恒为 0**；补齐后漏斗/Token/CSAT 三块报表可按租户正常取数
20. **租户隔离加固（M5-5.5）**：①JWT 中间件解析 claims（`tid`/`tenant_id`、`sub`/`user_id`、`role`）注入可信租户身份，令牌非法或缺租户声明一律 401，鉴权关闭时回落 `GATEWAY_DEFAULT_TENANT` 并允许 `X-Tenant-Id` 联调头（仅本地联调）；②建会话/建单/工作流/报表的 `tenant_id` 一律以可信上下文为准，请求体或查询串与之不一致返回 403 并记告警日志 `[tenant-isolation-denied]`；③出站 gRPC 统一经 metadata 下传 `x-tenant-id`/`x-user-id`/`x-role`；④租户级令牌桶限流（大租户独立配额，`GATEWAY_TENANT_RPS`/`GATEWAY_TENANT_RATE_BURST`/`GATEWAY_TENANT_QUOTAS` JSON）；⑤访问日志补 tenant/user/role 维度；⑥限流器新增空闲条目清扫（防键空间无界增长）；⑦新增 gRPC 状态码 → HTTP 映射（越权/不存在不再一律 503）。**新增 auth 7 项、tenant 4 项、middleware 11 项单测（含 handler 伪造租户 403 用例），Go 单测全绿**
21. **运营后台管理接口通道（M5-5.6）**：新增管理接口 **REST 透传通道**——`/api/v1/auth/login|me|logout`、`/api/v1/users*`、`/api/v1/logs` 路由，**权威契约在 Java REST 层**，网关只做协议转换与响应原样回传（不解析响应体，保证状态语义透传）；**登录路由豁免鉴权**；**角色路由拦截**（studio/users/logs → `admin`；reports/agent → `admin` 或 `agent`；session 任意已认证；`admin` 为超级角色）；鉴权中间件支持「`Authorization: Bearer` 或查询参数 `token`」两种凭证（后者供浏览器 WSS 握手——浏览器 WebSocket 无法自定义请求头）；转发时**剔除 `token` 查询参数**避免令牌落入下游日志。**新增 `internal/handler/proxy_test.go` 4 项、`internal/middleware/require_role_test.go` 5 项单测，Go 全量单测通过**
22. **知识库 REST 反向代理（M5-5.6 6.5）**：新增 `internal/handler/kb_proxy.go`——以 `httputil.ReverseProxy` **流式转发**知识库 REST 请求（**支持 multipart 上传**，转发过程不在内存缓冲整包，**内存占用与文件大小无关**；后端不可达时回 503 JSON）；`cmd/gateway/main.go` 在 `api.Group("/kb", adminOnly)` 下注册 `Any("")` 与 `Any("/*rest")` 两条路由，覆盖 `/api/v1/kb/bases` 与 `/api/v1/kb/documents`（含 `/uploads`、`/uploads/{id}/parts`、`/uploads/{id}/complete`）全部子路径，**权限仅 `admin`**（网关侧拦截）

## 四、core-java（Java 业务中枢）

### 功能点

1. Maven 多模块父工程（依赖版本统一）
2. 统一响应体 `Result`（code/message/data）
3. 全局异常处理（业务异常/参数校验/兜底）
4. 业务异常 `BizException`（错误码 + 提示）
5. 启动聚合模块 + 应用配置
6. gRPC 契约模块（Maven protobuf 插件生成跨语言契约）
7. gRPC 健康检查服务端（网关 → Java ping 通）
8. **会话域模块 `session`（M2-A2）**：状态机（INIT/HUMAN_CHAT/CLOSED）、内存仓储、gRPC 服务实现（建会话/发消息/迁移/续传）
9. **客服队列与接管（M2-B2）**：待接管列表、坐席抢单（并发仅成功一次）、坐席会话列表
10. **工单域模块 `ticket`（M2-B4）**：工单状态机（CREATED→PROCESSING→CLOSED）、MySQL 持久化（条件更新防并发覆盖）、gRPC 服务
11. **WebClient 基础设施（M2-B3）**：Servlet 栈下出站 HTTP 客户端（连接/响应超时可配置），供 M3 AI 快捷回复与第三方集成
12. **本地中间件接线（M2）**：MySQL 数据源 + Redis 单机 + schema.sql 幂等建表
13. **会话事件发布（M3-3.8）**：`SessionEventPublisher` 依赖倒置端口（会话域只声明需求）+ `NoOpSessionEventPublisher` 空实现；用户消息落库后发布 `lingxi.session.message`（坐席回复不触发，避免循环应答），会话键分区保序，序列化/投递失败记录不阻断 gRPC 应答

## 五、ai-python（Python AI 域）

### 功能点

1. FastAPI 应用入口与健康检查
2. 环境变量化配置（`LINGXI_` 前缀，含 DeepSeek 密钥/模型）
3. **LLM 网关（M3-3.1 完整版）**：多模型降级链（DeepSeek 主 → qwen / glm / kimi 备，按 `LINGXI_LLM_PROVIDER_CHAIN` 配置顺序降级）+ 指数退避重试 + 超时（首字 10s / 总 120s）+ 非流式/流式双通道降级；`create_gateway` 工厂**仅纳入已配置密钥的 Provider**（未配置者跳过并告警，避免无谓的首字超时等待），DeepSeek/qwen/glm/kimi 共用 OpenAI 兼容基类；故障演练（多级备用依次失效仍由末位兜底）单测通过；非流式响应记录 Token 用量审计
4. 云端 Provider 接入（OpenAI 兼容协议统一基类）：DeepSeek / 通义千问（DashScope 兼容模式）/ 智谱 GLM-4 / Kimi（Moonshot），各家 base_url/model 由独立配置块注入
5. 非流式生成验证接口
6. **知识库文档解析与结构感知切分（M3-3.3）**：7 类文档解析（PDF / Word / PPT / Excel·CSV / HTML / Markdown / 纯文本）+ 结构感知递归切分 + 父子块生成（子块 256~512 token 检索、父块 1k~2k token 回填）+ 元数据注入（heading_path / 页码 / 工作表）+ 相邻子块重叠防跨块断裂
7. **Milvus 集合与入库管道（M3-3.5）**：子块 Collection（稠密 `FLOAT_VECTOR` + 稀疏 `SPARSE_FLOAT_VECTOR`、HNSW + SPARSE_INVERTED 索引、`tenant_id` Partition Key 多租户隔离）、逻辑别名零停机版本切换、按 `doc_id` 全量替换（先删后插）、父块按 `parent_id` 聚合回填、Embedding 抽象（bge-m3 生产 / hash 离线）、入库编排（解析→切分→向量化→索引→状态回写钩子）
8. **Embedding 通道（M3-3.4 方案 C：云端稠密 + 本地稀疏；M3-3.8 延迟优化）**：`CloudDenseEmbedder`（Provider 无关的 OpenAI 兼容 `/v1/embeddings`，默认指向国内低延迟服务 `BAAI/bge-m3`，批量 + 超时 + 指数退避 + 维度校验）、`KeywordSparseEmbedder`（jieba 分词 + BM25 风格 TF 饱和 + 长度归一化，纯 CPU 毫秒级）、`HybridEmbedder`（组合二者写入 Milvus 双字段，保留混合检索）、`CachedEmbedder`（查询向量缓存 LRU + TTL，命中即跳过云端网络往返——首字延迟优化）、`BgeM3Embedder`（本机 FlagEmbedding 自部署备选，原生稠密+稀疏）
9. **混合检索与精排（M3-3.6；M3-3.8 延迟优化）**：`ChunkStore.search_chunks`（稠密 + 稀疏双路检索、RRFRanker 融合、`tenant_id` 强制过滤、稀疏缺失时退化为纯稠密）、`Retriever`（召回 Top-K（默认 10，可配；下调以降低精排耗时）→ 精排 Top5 → 按 `parent_id` 聚合回填父块，同一父块命中去重缓存）、`CloudReranker`（云端 bge-reranker-v2-m3，超时 + 指数退避 + 下标范围校验，复用长连接）、`IdentityReranker`（精排失败/密钥缺失时降级为 RRF 融合顺序，不阻断检索）
10. **Agent 运行时最小图（M3-3.7）**：LangGraph `StateGraph` 三节点主路径（加载上下文 → 混合检索精排 → 生成），依赖注入（`retriever` / `gateway` 由外部装配，节点不含具体实现）、检索失败降级为空上下文继续生成、提示词按「系统提示 + 知识片段（父块优先）+ 对话历史 + 用户问题」拼装、近期历史按上限裁剪；**检索（同步阻塞的嵌入 HTTP + Milvus）经 `asyncio.to_thread` 放入工作线程执行，不阻塞事件循环**（多会话并发可真正并行）；`create_agent` 由文档存储装配检索器并编译图；FastAPI 暴露非流式对话接口 `POST /api/v1/agent/chat`（惰性装配单例、双检锁防并发重复构建），返回回答与引用来源
11. **流式全链路（M3-3.8，Kafka 异步主路径）**：LLM Provider SSE 流式（`stream_chat` 逐行解析，基类默认退回非流式保证全 Provider 可用）+ 网关流式降级（首字超时保护、已产出片段后不重复降级）；`stream_answer` 复用图表逻辑产出 `context/delta/done` 事件；Kafka 封装（生产者 + 通用消费循环，会话键分区保序、单条失败不中断）；会话消息消费编排（`lingxi.session.message` → 流式生成 → 逐片段发 `lingxi.ai.chunk` + 终帧 → 完整回答发 `lingxi.ai.reply`）；FastAPI lifespan 按开关拉起消费协程（异步任务异常显式记录）；进程内运行时单例（Milvus/检索器/Agent 图/Kafka 生产者）
12. **知识库入库与下线消费（M3-3.2）**：消费 `kb.doc.ingest` → 经预签名 URL 下载原始文档到临时文件（保留扩展名供解析器分派，下载与入库均放工作线程不阻塞事件循环）→ 解析/切分/向量化/写入 Milvus（按 doc_id 全量替换）→ 投递 `kb.doc.indexed` 回写文档状态；**失败同样回写 FAILED**（避免文档永久停留「处理中」），临时文件无论成败均清理；另消费 `kb.doc.delete` 按 `doc_id + tenant_id` 清理向量切片（独立消费组）；Embedding 单例装配（M3-3.4 工厂）
13. **PII 脱敏与还原（M3-3.9）**：`PiiMasker` 会话级脱敏器——手机号/身份证/银行卡/邮箱（强正则）+ 中文地址（启发式，可开关）识别为占位符（如 `[手机号1]`）；**进模型前脱敏**覆盖用户问题、对话历史、检索到的知识片段（云端 embedding 亦不外泄，入库向量化前同样遮蔽、原文仍入库供引用）；**输出侧还原**含非流式回答与**流式片段**（按占位符边界缓冲，跨片段切断也能正确还原）；边界处理：占位符与原文冲突时顺延序号、多类 PII 重叠按「最长 + 优先级 + 非重叠」取舍（地址内的号码随地址整体隐藏）、同一原文跨字段复用同一占位符；真实端到端验证：送入 DeepSeek 的提示词中无真实 PII、回答还原后含真实值
