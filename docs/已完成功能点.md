## 三、gateway-go（Go 接入网关）

### 功能点

1. 网关启动入口与路由装配
2. 访问日志中间件（请求审计）
3. 令牌桶限流（按客户端 IP）
4. JWT 鉴权（M1 占位，M2 签名校验）
5. 健康检查接口
6. gRPC 契约代码（gen-proto.sh 生成）
7. gRPC 客户端封装（网关 → Java 域 ping 链路）
8. **WSS 长连接网关（M2-A3）**：连接管理、心跳 ping/pong、断连缓冲（环形 200 条）+ seq 续传、消息路由
9. **会话域 gRPC 客户端（M2）**：建会话/发消息/拉取续传，5s 超时
10. **用户端建会话接口（M2）**：`POST /api/v1/session` 转发 Java 会话域
11. **坐席回复下行接口（M2）**：`POST /api/v1/agent/reply` 落库 Java 后广播下行
12. **实时链路集成测试（M2-A5）**：用户↔网关↔Java 全链路闭环验证
13. **客服工作台接口（M2-B5）**：`GET /api/v1/agent/queue` 客服队列、`POST /api/v1/agent/takeover` 接管抢单、`GET /api/v1/agent/sessions` 坐席会话列表
14. **工单域接口（M2-B5）**：`POST/GET /api/v1/agent/tickets` 建单/列表、`POST /api/v1/agent/tickets/:id/status` 状态流转
15. **AI 流式片段推送（M3-3.8）**：`chunk` 下行信封（`index`/`finished` 显式下发，前端据此打字机与收尾）、Kafka 片段消费者（`lingxi.ai.chunk` → Hub 广播至会话连接，单条消息失败不中断循环、ctx 取消优雅退出）、`GATEWAY_KAFKA_*` 开关与地址配置（默认关闭，本地无 Kafka 也能启动）
16. **编排 Studio 接口（M4-4.7）**：`/api/v1/studio/workflows` 九条路由——列表、新建、详情、保存草稿（`PUT .../draft`，请求体直接承载画布图对象，Go 原样转 JSON 文本上送）、发布、版本列表、版本详情、回滚、删除；gRPC 编排域客户端（复用 Java 同一地址，5s 超时）；参数缺失/非法 400、通道故障 503、业务拒绝以 `{ok:false, reason}` 返回（与工单域约定一致）
17. **灰度发布与分流接口（M4-4.8）**：新增 `POST /api/v1/studio/workflows/:id/rollout`（网关只做范围校验：`canary_percent ∈ [0,100]`、开启灰度必须带 `canary_version`，业务规则收敛到 Java）；发布接口增 `canary` 开关（灰度发布）；`workflowView` 增 `canary_version`/`canary_percent` 并随列表/详情下发；客户端新增 `Rollout`、`PublishWorkflow` 增 `canary` 参数

## 四、core-java（Java 业务中枢）

### 功能点

1. Maven 多模块父工程（依赖版本统一）
2. 统一响应体 `Result`（code/message/data）
3. 全局异常处理（业务异常/参数校验/兜底）
4. 业务异常 `BizException`（错误码 + 提示）
5. 启动聚合模块 + 应用配置
6. gRPC 契约模块（Maven protobuf 插件生成跨语言契约）
7. gRPC 健康检查服务端（网关 → Java ping 通）
8. **会话域模块 `session`（M2-A2）**：状态机（INIT/HUMAN_CHAT/CLOSED）、内存仓储、gRPC 服务实现（建会话/发消息/迁移/续传）
9. **客服队列与接管（M2-B2）**：待接管列表、坐席抢单（并发仅成功一次）、坐席会话列表
10. **工单域模块 `ticket`（M2-B4）**：工单状态机（CREATED→PROCESSING→CLOSED）、MySQL 持久化（条件更新防并发覆盖）、gRPC 服务
11. **WebClient 基础设施（M2-B3）**：Servlet 栈下出站 HTTP 客户端（连接/响应超时可配置），供 M3 AI 快捷回复与第三方集成
12. **本地中间件接线（M2）**：MySQL 数据源 + Redis 单机 + schema.sql 幂等建表
13. **会话事件发布（M3-3.8）**：`SessionEventPublisher` 依赖倒置端口（会话域只声明需求）+ `NoOpSessionEventPublisher` 空实现；用户消息落库后发布 `lingxi.session.message`（坐席回复不触发，避免循环应答），会话键分区保序，序列化/投递失败记录不阻断 gRPC 应答
14. **AI 回答落库（M3-3.8）**：`AiReplyConsumer` 消费 `lingxi.ai.reply`，按上游 `ai-<uuid>` 消息 ID 幂等落库为助手消息（重复投递跳过），使断连续传/历史回源能取到 AI 回答（前端按同一 ID 归并流式内容，避免重复渲染）
15. **知识库域模块 `knowledge`（M3-3.2）**：知识库/知识分类/文档元数据 CRUD（DDD 四层：api/application/domain/infrastructure，JdbcTemplate + schema.sql 建表）；文档上传落 MinIO 对象存储（路径 `tenant/kb/doc/version`）、**内容 SHA-256 去重**（库内唯一索引 `uk_kb_hash`）、**版本管理**（同 docId 覆盖新版本并使状态回到待入库，Milvus 按 docId 全量替换）、**超大文档分片上传**（初始化 → 逐片上传（可乱序/重传）→ 合并校验分片齐全后按序号拼接并计算哈希）；文档切片状态机 PENDING/INDEXED/FAILED/DELETED
16. **入库任务下发与状态回写（M3-3.2）**：`KnowledgeEventPublisher` 依赖倒置端口（+ `NoOpKnowledgeEventPublisher` 空实现）；上传落库后投递 `kb.doc.ingest`（携带预签名下载 URL，免去 AI 域引入对象存储 SDK）；`KbIndexedConsumer` 消费 `kb.doc.indexed` 回写文档状态与子块/父块统计，**仅版本号匹配时更新**（拒绝旧版本迟到事件覆盖新版本状态）

## 五、ai-python（Python AI 域）

### 功能点

1. FastAPI 应用入口与健康检查
2. 环境变量化配置（`LINGXI_` 前缀，含 DeepSeek 密钥/模型）
3. **LLM 网关（M3-3.1 完整版）**：多模型降级链（DeepSeek 主 → qwen / glm / kimi 备，按 `LINGXI_LLM_PROVIDER_CHAIN` 配置顺序降级）+ 指数退避重试 + 超时（首字 10s / 总 120s）+ 非流式/流式双通道降级；`create_gateway` 工厂**仅纳入已配置密钥的 Provider**（未配置者跳过并告警，避免无谓的首字超时等待），DeepSeek/qwen/glm/kimi 共用 OpenAI 兼容基类；故障演练（多级备用依次失效仍由末位兜底）单测通过；非流式响应记录 Token 用量审计
4. 云端 Provider 接入（OpenAI 兼容协议统一基类）：DeepSeek / 通义千问（DashScope 兼容模式）/ 智谱 GLM-4 / Kimi（Moonshot），各家 base_url/model 由独立配置块注入
5. 非流式生成验证接口
6. **知识库文档解析与结构感知切分（M3-3.3）**：7 类文档解析（PDF / Word / PPT / Excel·CSV / HTML / Markdown / 纯文本）+ 结构感知递归切分 + 父子块生成（子块 256~512 token 检索、父块 1k~2k token 回填）+ 元数据注入（heading_path / 页码 / 工作表）+ 相邻子块重叠防跨块断裂
7. **Milvus 集合与入库管道（M3-3.5）**：子块 Collection（稠密 `FLOAT_VECTOR` + 稀疏 `SPARSE_FLOAT_VECTOR`、HNSW + SPARSE_INVERTED 索引、`tenant_id` Partition Key 多租户隔离）、逻辑别名零停机版本切换、按 `doc_id` 全量替换（先删后插）、父块按 `parent_id` 聚合回填、Embedding 抽象（bge-m3 生产 / hash 离线）、入库编排（解析→切分→向量化→索引→状态回写钩子）

## 六、web-vue3（Vue3 前端）

### 功能点

1. 应用装配（Pinia + Router + Naive UI）
2. 路由（用户端会话页 `/`、客服工作台 `/workbench`、Agent 编排 Studio `/studio`；管理台预留）
3. HTTP 请求封装（axios 统一解包）
4. SSE 流式工具（ReadableStream 拆分渲染）
5. **WSS 长连接封装（M2-A4）**：会话创建、收发信封、断连指数退避重连 + resume 续传、刷新回源拉历史
6. **用户端会话页（M2-A4）**：实时消息列表、发送/接收、连接状态展示、手动重连
7. **客服工作台 API 层（M2-C2）**：队列/接管/坐席会话/工单/回复接口封装
8. **工作台状态管理（M2-C3）**：队列 5s 轮询、选中会话 WSS 观察端（resume(0) 回源历史）、接管、回复、一键建单、工单流转
9. **客服工作台页面（M2-C4）**：三栏布局（待接管队列/我的会话｜消息区+接管+回复｜工单建单与流转），窄视口横向滚动
10. **流式打字机渲染（M3-3.8）**：`chunk` 信封处理（累加片段为首条助手消息、`finished` 结束打字机态、`error` 提示）；落库消息按 `message_id` 归并（与流式内容合并为同一条，避免重复渲染）；闪烁光标与内容增长自动滚动
11. Nginx 部署配置（SPA 回退 + API 转发）
12. **Agent 编排 Studio（M4-4.7）**：①画布（Vue Flow）——左侧节点面板「拖拽」四类节点（LLM 生成/知识检索/工具调用/条件分支）到画布，节点卡片按类型配色并展示配置摘要；节点可拖拽移位、可连线（`@connect` 拒绝自环与重复连线），分支节点卡片右侧暴露 **true/false 两条出边 handle**（连线带「是/否」标签）；②右侧「节点配置」面板按类型渲染字段（检索 kb_id/candidate_k/top_k、工具 tool_name 下拉（取自 AI 域工具注册表）/timeout_ms、分支 expression、LLM model/temperature/max_tokens/system_prompt），**文本类字段失焦提交**避免每次按键入历史栈；③**编辑态回滚**：快照式 undo/redo 栈（上限 50，`Ctrl/Cmd+Z` 撤销、`+Shift+Z` 重做），快照仅存「图定义」不带画布运行时字段，拖拽落位与增删节点/连线/配置变更均可撤销；④**版本级回滚**：版本抽屉列出快照（版本号/发布说明/操作者/时间 + 查看 + 回滚到 vN），查看为只读 JSON 预览，「回滚」把该版本内容复制为当前草稿并提示「复核后请重新发布」；⑤顶部工具栏：工作流选择/新建/删除、`生效 vN`/`未发布` 状态标签、`未保存` 脏标记、撤销/重做/删除选中、保存草稿（`Ctrl/Cmd+S`）/发布/版本；⑥**打开页面默认选中第一条工作流**并自动适配视图（编辑器首屏不留空画布）
   - 依赖新增：`@vue-flow/core` 1.48.2 + `@vue-flow/background` 1.3.2 + `@vue-flow/controls` 1.1.3 + `@vue-flow/minimap` 1.5.4（MIT，Vue3 原生；Vue Flow v1 未内置「外部拖入」协议，画布 drop 由页面自行接管 + `screenToFlowCoordinate` 换算落点）
13. **灰度配置与版本分流界面（M4-4.8）**：①发布弹窗新增「灰度发布（不立即生效，由「版本 → 灰度分流」按比例放量）」复选框——勾选后 `latest` 前进而生效版本不变（与后端 `canary` 语义一致）；②版本抽屉新增「灰度分流」区（灰度版本下拉 + 分流比例 0~100 + 「保存灰度」/「关闭灰度」按钮 + 「当前：vN · P%」或「未启用灰度」提示），版本条目新增「设为灰度」快捷按钮（沿用当前比例，默认 10%）；③顶部工具栏在 `canary_percent > 0` 时显示 `灰度 vN · P%` 标签（info 色），关闭灰度后自动消失；④`api/studio.ts` 增 `setRollout`、`StudioWorkflow` 增 `canary_version`/`canary_percent`、`publishWorkflow` 增 `canary` 参数；⑤`useStudio` 增 `rolloutTo(version, percent)`（`percent=0` 关闭灰度并回归生效版本，拒绝时以 reason 提示）；⑥**修复 `n-space` 内条件渲染子项导致的 Vue「Duplicate keys」告警**（为工具栏子元素补显式 key）

### Kafka 事件契约（M3-3.8 流式全链路）

> 事件体为 JSON，统一以 `session_id` 作消息键（保证同会话有序）；主题名可用 `LINGXI_KAFKA_TOPIC_*` 覆盖。

| 主题 | 方向 | 事件体字段 |
|---|---|---|
| `lingxi.session.message` | Java → Python | `session_id`、`tenant_id`、**`user_id`（M4-4.4，跨会话记忆隔离）**、`message_id`、`seq`、`content`、`summary`、`history` |
| `lingxi.ai.chunk` | Python → Go | `session_id`、`message_id`（`ai-<uuid>`）、`index`、`delta`、`finished`、`error`（终帧携带）、**`interrupted` + `reason`（M4-4.5：接管中断终帧，与 `error` 分开表达）** |
| `lingxi.ai.reply` | Python → Java | `session_id`、`tenant_id`、`message_id`、`content`（完整回答）、`reply_to`（用户消息 ID）；**被接管中断时不下发**（避免落库半截回答） |
| `lingxi.session.summary` | Python → Java | `session_id`、`summary`（M3-3.11 会话摘要回写，Java 幂等覆盖） |
| `lingxi.ai.handoff` | Python → Java | `session_id`、`tenant_id`、`message_id`、`reason`（`user_request`/`emotion`/`low_confidence`）、`seq`（M4-4.5：Java 消费后转入 `WAITING_HUMAN`） |
| `lingxi.session.takeover` | Java → Python | `session_id`、`reason`（`agent_takeover`/`handoff_requested`/`state_change`）、`agent_id`、`at_ms`（M4-4.5：AI 侧据此立即终止正在生成的回答） |
| `lingxi.ai.suggest.request` | Java → Python | `request_id`、`tenant_id`、`session_id`、`agent_id`、`intent`、`summary`、`history[{role,content}]`、`max_suggestions`（M4-4.6：同步通道超载后的异步降级请求；**仅 Java 投递**） |
| `lingxi.ai.suggest.result` | Python → Go | `session_id`、`request_id`、`suggestions[]`（M4-4.6：异步建议结果，Go `BroadcastToRole(…, "agent")` **只推坐席端**，防泄漏给用户端） |
