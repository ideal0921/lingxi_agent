## 三、选型决策

用户已确认（均为推荐项）：

1. **画布库 = Vue Flow**（`@vue-flow/core` + background/controls/minimap）：Vue3 原生、MIT、体积小。
2. **持久化落点 = Java 新增编排域 + Go 转发**：`Vue → /api/v1/studio/* → Go → gRPC → Java → MySQL`。
3. **回滚语义 = 版本级回滚 + 编辑态撤销重做**：
   - 版本级：把历史版本内容**复制为当前草稿**（不新增版本、不改生效版本，可再审阅后重新发布 → 生成新版本号，历史不被破坏、可审计）。
   - 编辑态：前端 undo/redo 栈（Ctrl+Z / Ctrl+Shift+Z）。

本计划自定的其余决策（受需求与既有能力约束，非开放项）：

| 决策 | 取值 | 理由 |
| --- | --- | --- |
| Java 模块名 | `core-java/workflow`（artifact `lingxi-workflow`，包 `com.lingxi.workflow`） | 与 `knowledge`/`business` 同级，语义直白 |
| 图定义载体 | proto 只传 `definition_json`（string），Java 用 Jackson 解析后校验 | 节点配置为开放 JSON，避免为每类节点建 proto 消息；前端掌握画布格式 |
| 节点类型 | `LLM` / `RETRIEVE` / `TOOL` / `BRANCH` 四类（入口以「入度 0」隐式表达，不额外加 START 节点） | 严格对齐需求原话，不引入未要求的节点 |
| 分支表达 | 分支节点出边带 `condition ∈ {ALWAYS, TRUE, FALSE}` | 不引入表达式引擎（安全风险 + 超出本期），条件字符串仅存储，求值留 4.8 白名单评估 |
| 生效版本读取 | `GET .../published` 返回主体 + `published_version` 的 definition；4.8 直接消费 | 为 4.8 预留稳定读口，本期仅落接口 |

## 五、关键设计细节

### 5.1 工作流图 JSON Schema（跨语言唯一契约，4.8 复用）

```json
{
  "nodes": [
    { "id": "n1", "type": "retrieve", "name": "知识检索",
      "config": { "kb_id": "kb-xxx", "candidate_k": 10, "top_k": 5 } },
    { "id": "n2", "type": "branch", "name": "置信度分支",
      "config": { "expression": "top_score >= 0.6" } },
    { "id": "n3", "type": "tool", "name": "查订单",
      "config": { "tool_name": "query_order", "timeout_ms": 5000 } },
    { "id": "n4", "type": "llm", "name": "生成回答",
      "config": { "model": "", "temperature": 0.7, "max_tokens": 1024, "system_prompt": "" } }
  ],
  "edges": [
    { "id": "e1", "source": "n1", "target": "n2", "condition": "always" },
    { "id": "e2", "source": "n2", "target": "n4", "condition": "true"  },
    { "id": "e3", "source": "n2", "target": "n3", "condition": "false" }
  ]
}
```

节点必填 config：
- `llm`：全部可选（`model` 空 = 走网关降级链）
- `retrieve`：`kb_id` 必填；`candidate_k`/`top_k` 可选（默认 10 / 5，对齐 `LINGXI_RETRIEVE_CANDIDATE_K/TOP_K`）
- `tool`：`tool_name` 必填；`timeout_ms` 可选（默认 5000）
- `branch`：`expression` 必填（**仅存储，本期不求值**）

### 5.2 校验规则（`WorkflowGraphValidator`，保存草稿仅做结构解析，**发布时全量校验**）

1. 图非空、`definition_json` 字节数 ≤ `definition-max-bytes`
2. 节点 id 唯一；`type` ∈ 四类；`config` 为对象
3. 边 id 唯一；`source`/`target` 必须指向存在的节点；无自环；无重复 (source,target)
4. 入度 0 的节点**有且仅有 1 个**（隐式入口）
5. **有向无环**（Kahn 拓扑排序；存在未出队节点即判定成环）
6. 每个 `branch` 节点出边恰好两条，`condition` 分别为 `TRUE` 与 `FALSE`
7. 非 `branch` 节点出边 `condition` 必须为 `ALWAYS`
8. 各节点 config 必填字段（见 5.1）

任一不满足 → 发布被拒（`ok=false` + 中文原因），草稿始终可保存（宽松，避免编辑过程被卡）。

### 5.3 版本与回滚语义

| 动作 | 效果 |
| --- | --- |
| 保存草稿 | 只写 `lingxi_workflow.draft_definition`，版本号不变 |
| 发布 | 校验通过 → `latest_version+1` 写入 `lingxi_workflow_version`（快照冻结）→ 更新 `latest_version` / `published_version` = 新版本号；草稿保留（便于继续迭代） |
| 版本列表 | 读 `lingxi_workflow_version`，按 version 倒序 |
| 查看快照 | 读该版本 `definition`（**只读，不影响草稿**） |
| 回滚到 v N | 将该版本 `definition` 复制进 `draft_definition`；**不新增版本、不改 published_version** → 运营复核后再点发布生成新版本（历史完整、可审计） |
| 删除工作流 | 删主体 + 删其全部版本快照 |

### 5.4 画布撤销/重做（`useStudio`）

- 快照式栈：`undoStack: WorkflowGraph[]` / `redoStack: WorkflowGraph[]`，每次**结构性变更前**（增删节点、连线、删边、拖拽落位结束、配置提交）push 当前图。
- 深拷贝用 `structuredClone`（此处必须拷贝：栈内对象若与画布共享引用，后续编辑会污染历史）。上限 50 步，超出丢弃栈底。
- `Ctrl+Z` 撤销 / `Ctrl+Shift+Z` 重做；`Ctrl+S` 保存草稿（`@keydown` 绑定在画布容器，`preventDefault` 避免浏览器默认行为）。
- 撤销/重做后 `dirty=true`，提示未保存。
