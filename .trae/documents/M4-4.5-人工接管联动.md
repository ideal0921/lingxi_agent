# M4-4.5 人工接管联动 实施计划

## Context（为什么做、要达成什么）

M4 里程碑要求 Agent 具备「工具调用、记忆、**人工接管联动**」。现状：
- M2-B/M2-C 已完成**坐席主动接管**（`Session.takeOver` 并发仅 1 成功）+ 客服队列 + 工作台；M3-3.11 已完成 `AI_ACTIVE` 状态与摘要在会话内流转。
- 但**「AI 主动请求转人工」尚不存在**：无低置信度/用户明示/情绪三类触发规则，无 Python 侧的判定；AI 请求转人工也没有落点状态。
- **「接管瞬间终止正在生成的回答」做不到**：Java→Python 目前只有 `lingxi.session.message` 一个信道，Python 的 `stream_answer` 没有任何取消点，正在生成的半截回答照旧发完并落库。
- **摘要无法移交坐席**：`SessionSummary` 不含 `summary`，工作台队列只能看到条数/时间。

本任务交付三点：①三类规则触发转人工；②接管/转人工瞬间终止生成且不落库半截回答；③摘要随队列移交坐席。

## 已确认路线（用户已选定，不提供替代方案）

1. **触发判定在 Python**，命中即**不生成 AI 回答**，改发新主题 `lingxi.ai.handoff`（Python→Java，JSON，key=session_id）通知 Java。
2. **新增会话状态 `WAITING_HUMAN`**：仍在客服队列、不再触发 AI；坐席接管 → `HUMAN_CHAT`。
3. **终止生成 = 反向事件 + 片段检查点**：Java 接管/转人工成功 → 发布 `lingxi.session.takeover` → Python 新消费者写「中断集合」→ 生成循环**每片段前检查**，命中即停止、发 `interrupted` 终帧、**不落库半截回答**。
4. **摘要移交 = `SessionSummary` 加 `summary` 字段**，Java→Go→前端透传，接管前的队列列表即可见。

## 关键设计决策（边界与风险）

### D1. 检查点放在消费侧（不改 `stream_answer` 契约）
中断判定放在 `handle_session_message` 的片段循环内（`CONTEXT` 后做规则判定；每个 `DELTA` 发布前做中断检查），**不改 `stream_answer` 签名**——它是纯生成器，中断集合属消费者运行时态，注入图会污染契约、并影响非流式路径。中断粒度 = 1 个片段（接管最多多发 1 片，几十 ms）。

### D2. 中断必须区分「中断」与「错误」
终帧新增 `interrupted`（bool）与 `reason`（字符串），**不复用 `error`**——前端 `useChat` 会把 `finished && error` 渲染成错误横幅，而「已转人工」是正常业务态。`reason` 取值 `agent_takeover` / `handoff_requested`，前端据此生成提示语。

### D3. 中断集合的生命周期（防泄漏 + 防误伤）
- **写入**：收到 `lingxi.session.takeover` 事件（session_id → reason）。
- **读取**：每片段前查（只读不删，避免多次命中语义混乱）。
- **清理**：①同会话**下一条消息开始处理时**先清一次（消解迟到事件、避免误伤后续轮次）；②TTL `agent_handoff_interrupt_ttl_seconds=300` 惰性过期（防内存泄漏）。
- 纯内存 dict，**单事件循环内读写天然原子，无需加锁**。

### D4. 终止的落库边界
命中中断 → **不发 `lingxi.ai.reply`**（否则半截回答被 Java 落库成权威助手消息）。用户端已渲染的文本保留 + 追加「已转人工」态（见 D5），不视为错误。

### D5. 前端「已转人工」呈现
`chunk` 终帧带 `interrupted=true` → `useChat` 结束打字机、置消息级 `interrupted` 标记（**不写 `error`**），显示「已转人工，正在为您安排坐席」；保留已显示片段（不移除）。

### D6. 三类规则（优先级：用户明示 > 情绪 > 低置信度）
- **用户明示**：`agent_handoff_user_keywords`（默认 `转人工,人工客服,人工服务,找人工,转接人工`），归一化（去空白 + 小写）后子串匹配。
- **情绪**：`agent_handoff_emotion_keywords`（投诉/举报/骗子/诈骗/垃圾/退钱/赔偿/维权/差评/监管/报警/告你们），`agent_handoff_emotion_min_hits` 默认 **2**（防单词误伤）。
- **低置信度**（稳妥做法）：①**命中为空**（`agent_handoff_empty_hits_enabled=true`，与分数量纲无关）；②精排分低于阈值（`agent_handoff_low_score_enabled=false` 默认关，`agent_handoff_low_score_threshold=0.3`）——**仅在 `rerank_provider != "none"` 且密钥存在**（此时 `RetrievalHit.score` 确为精排分）时才启用；RRF 分与精排分**量纲不同，不可比**，故默认关闭阈值规则，避免误判。
- 命中行为：发布固定话术 `agent_handoff_reply_text`（复用既有 chunk/`ai.reply` 通道，用户端打字机体验一致，Java 落库该话术），随后发 `lingxi.ai.handoff`。

### D7. WAITING_HUMAN 的连带影响
迁移表：`INIT→{AI_ACTIVE, WAITING_HUMAN, HUMAN_CHAT, CLOSED}`、`AI_ACTIVE→{WAITING_HUMAN, HUMAN_CHAT, CLOSED}`、`WAITING_HUMAN→{HUMAN_CHAT, CLOSED}`、`HUMAN_CHAT→{CLOSED}`、`CLOSED→{}`。
- **队列查询必须加 `WAITING_HUMAN`**（否则转人工会话掉出队列，坐席看不到）。
- `aiAnswerable()`（INIT/AI_ACTIVE）**无需改**——`WAITING_HUMAN` 自动不命中 → 转人工后用户新消息不再触发 AI。
- **既有测试需更新**：`SessionStateMachineTest`（补新状态迁移断言）；`SessionEventPublishTest` 的 `RecordingPublisher` **必须实现新端口方法 `publishTakeover`**（否则编译失败）。

### D8. 摘要预览截断
`toProtoSummary` 内截断至 `lingxi.session.summary-preview-len`（默认 200 字符）——实体存储仍保 2000 上限，避免队列列表 payload 膨胀。

### D9. Kafka 关闭时降级
Java：`HandoffConsumer` 与 `KafkaSessionEventPublisher` 均 `@ConditionalOnProperty(lingxi.kafka.enabled=true)`；`SessionEventPublisher` 新方法 `publishTakeover` 在 `NoOpSessionEventPublisher` 中空实现（沿用既有依赖倒置 + FallbackConfig 范式）。
Python：`kafka_enabled=false` 时不起接管消费协程；无 producer 时规则空转、正常回答。

## 端到端验证（真实链路）

前置：`scripts/kafka-local.sh restart`（含 `init-topics` 建两个新主题）→ 重启 Java（`mvn -DskipTests install` 后重跑 jar）+ Python（`LINGXI_KAFKA_ENABLED=true`）+ Go 网关（端口 8080）。

1. **用户明示转人工**：用户端 WSS `send`「我要转人工」→
   ① Python 日志出现规则命中（`reason=user_request`）；
   ② `kafka-console-consumer --topic lingxi.ai.handoff --from-beginning` 见 `{session_id, reason:"user_request"}`；
   ③ Java 日志出现「进入 WAITING_HUMAN」；
   ④ `curl 'http://127.0.0.1:8080/api/v1/agent/queue?limit=20'` 该会话 **`state=WAITING_HUMAN` 且 `summary` 字段非空**（仍在队列）；
   ⑤ 再发一条用户消息 → **不再有 AI 应答**。
2. **生成中接管终止**：发起一个较长问题，在生成期间 `curl -X POST http://127.0.0.1:8080/api/v1/agent/takeover -d '{"session_id":"…","agent_id":"agent-01"}'` →
   ① `kafka-console-consumer --topic lingxi.session.takeover` 有事件；
   ② Python 日志「命中中断，停止产出」；
   ③ 前端打字机停止且提示「已转人工」；
   ④ `kafka-console-consumer --topic lingxi.ai.reply` **无该 `ai-<uuid>`**（未落库半截回答）；
   ⑤ `curl 'http://127.0.0.1:8080/api/v1/agent/sessions?agent_id=agent-01'` 显示 `HUMAN_CHAT`。
3. **摘要移交**：同一会话多轮（>20 条）触发 `lingxi.session.summary` 回写后，查 ① 的队列接口，`summary` 非空且长度 ≤ 200。
4. **降级**：`LINGXI_KAFKA_ENABLED=false` 启动 Python → 规则空转、问答正常、无异常。
