> 里程碑：M4 Agent 化 ｜ 任务：4.8（AI 域）

> 前置：M4-4.7 已交付编排域（`workflow.proto` + Java `workflow` 模块 + Go `/api/v1/studio/*` + Vue Studio），图定义 JSON Schema 已固定且「与 4.8 运行时共用同一份 Schema」

## 一、Context（为什么做这一步）

M4-4.7 把「编排」的**定义与版本**落库了（Java 编排域 + MySQL `lingxi_workflow`/`lingxi_workflow_version`，图定义以 JSON 文本冻结为不可变版本快照），但运行时仍是一条**硬编码的三节点图**（`ai-python/app/agent/graph.py` 的 `load_context → retrieve → generate`）。也就是说：Studio 里编排发布的工作流**当前完全不会被使用**。

M4-4.8 要补上这最后一环：
1. **按工作流版本加载图**——Python 运行时从 Java 编排域读取「生效版本」的图定义，把 JSON 图**编译成可执行的 LangGraph 图**并缓存；图里声明的 LLM/检索/工具/分支四类节点真正参与对话。
2. **路由版本灰度**——Java 编排域补上「已发布但未生效」的能力（灰度版本 + 分流比例），Python 按**会话稳定哈希**决定本次对话跑稳定版还是灰度版，从而让 Studio 能「发布并灰度一套工作流」。

预期结果：改 Studio 里的编排并发布，线上 AI 回答的流程随之改变；灰度可指定版本与比例、按会话稳定分流、可一键关闭。

## 三、选型决策（用户已确认，均为推荐项）

1. **图执行方式 = 编译为 LangGraph 动态图**：按版本把 JSON 图编译成 `StateGraph`，分支用 `add_conditional_edges`，LLM 节点用 `get_stream_writer()` + `astream(stream_mode="custom")` 流式。
2. **灰度控制面 = Java 编排域扩展**：新增 `canary_version`/`canary_percent` 与「灰度发布」「SetRollout」能力；Python 只读规则并按会话稳定哈希分桶。
3. **tool 节点语义 = 工具白名单声明**：tool 节点声明「本工作流允许使用该工具」，把工具面带到 LLM 节点，**完全复用 M4-4.1 的流式 Function Calling 循环**（模型自行决定何时调用、参数如何填）。

本计划自定的其余决策（受需求与既有能力约束，非开放项）：

| 决策 | 取值 | 理由 |
| --- | --- | --- |
| 灰度分桶 | `zlib.crc32(session_id) % 100 < canary_percent` → 灰度版，否则稳定版 | 确定性、可复现、**同一会话始终同一版本**（体验一致、便于复现问题） |
| 工具白名单收集 | **编译期**收集图中所有 `tool` 节点的 `tool_name`，注入到每个 LLM 节点闭包 | 无需改 `AgentState` 的 reducer 语义（避免 `Annotated[..., add]` 首次写入的边界问题）；语义清晰：工作流声明的工具面 |
| 版本变更感知 | 快照（rollout 规则）TTL 30s + 已编译图 TTL 300s/LRU | 避免每次对话都打 Java gRPC；发布后 ≤30s 生效，演示足够，且**不新增 Kafka 主题**（不扩到 12 个） |
| 分支表达式求值 | 自研**白名单 AST 校验**，只允许单次比较（变量/常量/比较运算符），**不调用 eval/compile** | 图定义是运营可编辑内容，绝不能进 `eval`；求值失败降级为走 `false` 出边并告警（`false` 按约定作为兜底路径） |
| 工作流归属 | `LINGXI_AGENT_DEFAULT_WORKFLOW_ID`（租户默认工作流）；事件未携带则用该默认值 | 不改 4 端会话契约即可跑通多工作流（不同环境/租户配不同工作流）；按会话绑定留作后续增量 |
| 降级 | 三重兜底回落内置图 `stream_answer` | 编排不可用绝不能拖垮问答主链路（也是 Golden Set 能继续通过的前提） |

## 五、关键设计细节

### 5.1 JSON 图 → LangGraph 编译规则

| 图元素 | 编译结果 |
| --- | --- |
| `retrieve` 节点 | 节点函数：`asyncio.to_thread(retriever.retrieve, query, tenant_id=, kb_id=config.kb_id, top_k=config.top_k)`；写 `{contexts, context_text}`；检索失败降级为空上下文（沿用既有 `noqa: BLE001` 降级语义）；并 `writer(StreamEvent(CONTEXT, contexts))` 让外层沿用**转人工判定** |
| `tool` 节点 | **编译期**把 `config.tool_name` 收进本图的 `allowed_tools` 集合（节点本身只做透传） |
| `branch` 节点 | 节点函数透传（不改状态）；其后用 `add_conditional_edges(node_id, router, {"true": ..., "false": ...})`，router 调 `expression.evaluate(expr, {top_score, hit_count, has_hits, query_length})`；求值失败 → 告警并取 `false` |
| `llm` 节点 | 节点函数：`allowed_tools` 非空 → `build_tool_messages` + `stream_tool_answer`；否则 `build_prompt` + `gateway.stream`；逐 delta 用 `get_stream_writer()` 写出 `StreamEvent(DELTA)`；返回 `{answer, prompt}` |
| 普通边 | `add_edge(source, target)`（Java 已保证非分支边只为 `always`） |
| 入口/终点 | 入度 0 的节点接 `START`；无出边的节点接 `END` |

**关键约定（复用既有不变式）**：
- 节点内只写**原始文本**片段，**不做 PII 还原**；外层 `run.py` 用**单条** `masker.restore_stream(...)` 包住整条 custom 流（沿用 M4-4.1 的「跨片段/跨轮次不被切断」约定）。
- 检索等同步阻塞一律 `asyncio.to_thread`（架构强制约束）。
- 图内异常**不得**向外抛断整轮：LLM 失败由 `gateway` 降级链兜底，检索失败降级空上下文。

**流式取用**：`async for chunk in graph.astream(state, stream_mode="custom")` → 外层仅透传 `StreamEvent` 实例（节点写入的对象），转成既有 `StreamEvent` 契约（`CONTEXT → DELTA* → DONE`），`DONE` 由 `run.py` 在图执行结束后补发。

### 5.2 版本灰度路由

```python
def resolve_version(session_id: str, snapshot: WorkflowSnapshot) -> int:
    """返回本次会话应使用的版本号；0 表示未发布（回落内置图）。"""
    if snapshot.canary_percent > 0 and snapshot.canary_version > 0:
        if stable_bucket(session_id) < snapshot.canary_percent:
            return snapshot.canary_version
    return snapshot.published_version

def stable_bucket(session_id: str) -> int:      # 0~99，确定性
    return zlib.crc32(session_id.encode("utf-8")) % 100
```

- 未配置 `agent_default_workflow_id` → 直接用内置图（不触达 Java）。
- `snapshot.published_version == 0`（从未发布）→ 回落内置图。
- 版本定义取不到 → 回落内置图并告警。
- 缓存：快照 TTL 30s（rollout 变更 ≤30s 生效）；已编译图按 `(workflow_id, version)` 缓存 TTL 300s + 容量上限 32。

### 5.3 表达式白名单求值（安全边界）

- 解析：`ast.parse(expr, mode="eval")`；**逐节点白名单**：仅 `Expression`/`Compare`/`Name`/`Constant`（含 `Load`）。
- 限制：`len(node.ops)==1 and len(node.comparators)==1`（禁止链式比较）；op ∈ `{Gt, GtE, Lt, LtE, Eq, NotEq}`；变量 ∈ `{top_score, hit_count, has_hits, query_length}`；常量仅 `int/float/str/bool`；**表达式长度上限**（config）。
- 求值：**按 AST 显式分派比较**（`operator.gt/ge/lt/le/eq/ne`），**不调用 `eval`/`compile`**；类型不可比时视为求值失败。
- 失败语义：记录告警 + 走 `false` 出边（`false` 为约定兜底路径）。

### 5.4 降级链（三重兜底，绝不拖垮问答）

1. 开关关闭 / 未配置默认工作流 → 内置 `stream_answer`
2. Java 编排域不可达 / 快照读取失败 → 内置 `stream_answer`（告警）
3. 图解析或编译失败 / 目标版本取不到 → 内置 `stream_answer`（告警）

图**内部**另有降级：检索失败 → 空上下文继续生成；LLM 失败 → 网关降级链；工具失败 → 执行器重试/降级话术。

## 六、假设与决策

1. **工具白名单为编译期全集**：图中任意 `tool` 节点声明的工具对**所有** LLM 节点可见（不做「按分支路径收敛工具面」）——简化且无害（白名单只做收敛不放权）。
2. **`candidate_k` 保留但不生效**：`Retriever` 的候选数仅在装配期可配（`LINGXI_RETRIEVE_CANDIDATE_K`），`retrieve` 节点本期只让 `kb_id` 与 `top_k` 生效；Studio 表单为 `candidate_k` 补一句「预留字段，运行期不生效」提示。
3. **不新增 Kafka 主题**：版本/灰度变更靠 TTL 轮询感知（≤30s），换取实现简单与主题数量稳定（仍为 11 个）。
4. **多工作流以「租户默认工作流」体现**：不同环境/租户配不同 `default_workflow_id`；会话级绑定留作后续增量（需改会话契约，超出本期）。
5. **Golden Set 口径不变**：runner 仍走内置图；新增 2 条用例作为回归护栏，工作流路径由专项单测与端到端灰度演练覆盖。
6. **`AgentState` 不做结构性改动**：不引入 `Annotated` reducer（工具白名单在编译期收集），仅加两个观测字段，避免影响既有两条路径。
