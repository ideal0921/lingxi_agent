# M4-4.4 记忆管理（跨会话用户级长期记忆）实施计划

## Context（为什么做、要达成什么）

M4 里程碑目标是让 Agent 具备「工具调用、记忆、人工接管联动」。其中：
- **M4-4.1 / 4.2 / 4.3（工具框架 / 业务工具接入 / 工具审计）已交付并通过真实端到端验证**；
- **长程摘要生成**已在 M3-3.11 完成，但只做到**会话级**（超窗旧消息压缩 → `lingxi.session.summary` → Java 回写 `Session.summary` → 下一轮携带回来）。

本任务的**净增量** = **跨会话（用户级）长期记忆**：把用户跨会话都值得记住的长期信息（偏好、身份角色、长期约束、反复诉求）沉淀为「每用户 1 条演进画像」，**按 `tenant_id` + `user_id` 严格隔离**，并在**新会话的每一轮**注入提示词，使 Agent 记得「这位用户之前是什么情况」。

痛点现状：`SessionMessageEvent` 事件体**不带 `user_id`**，AI 侧也无任何持久化存储（`pyproject` 无 redis/pymysql），故当前同一用户的新会话完全「失忆」。

## 已确认的实现路线（用户已选定，不再提供替代方案）

1. **存储形态**：AI 域 Redis，**每用户 1 条演进画像摘要**（KV，key 含 tenant + user 以隔离）。
2. **写入时机**：复用「超窗压缩」触发点（`publish_summary_if_needed` 出现 overflow 时）顺带合并画像；**普通短会话零额外模型调用**。
3. **注入方式**：**每轮**把画像直接拼进提示词（`【用户长期记忆】`，与会话摘要同级），无额外检索调用。

## 关键设计决策（含边界与风险处理）

### D1. PII 跨会话策略（关键）—— 画像「不存 PII、不存占位符」
`PiiMasker` 的 `_token_map` 是**会话级内存态**（`app/privacy/pii.py:166`），进程重启即丢失。若画像把会话 A 脱敏后的 `[手机号1]` 存进 Redis，新会话的 masker 无法把它还原成原文：既可能让模型把占位符当事实，也可能把占位符**字面量直接泄漏给用户**；而「读取时重新登记占位符」必须把原文一并落 Redis，等于明文持久化 PII，违背目标。

**结论：占位符绝不入库。** 三层防护：
1. **提示词层**：画像合并指令**禁止**记录手机号/身份证/银行卡/邮箱/地址等具体个人信息，且**禁止**输出 `[..]` 形态占位符；
2. **写入层**：`sanitize_profile()` 兜底（`strip_placeholders()` 去占位符 + `redact_pii()` 把残余 PII 替换为「（手机号）」类纯标签，**不产生 `[..]` 形态**）+ 长度截断；
3. **注入层**：`masker.mask(memory)` 二次兜底（历史脏数据/万一漏网，本轮 token_map 可正常还原）。

### D2. 不阻塞事件循环
用 `redis.asyncio`（异步客户端 + 连接池），经 `runtime._get` 惰性单例复用；**不做同步阻塞调用**，无需 `asyncio.to_thread`。

### D3. 隔离与越权
key = `lingxi:memory:profile:{tenant}:{user}`；`tenant_id`/`user_id` 中的 `:` 做转义；**`user_id` 为空 → `profile_key()` 返回 `None`，直接跳过读写**（不落库、不注入）。

### D4. 降级（与项目既有「静默降级 + 告警」风格一致）
Redis 不可用/超时 → `logger.warning` + `get_profile()` 返回 `""`、`save_profile()` 返回 `False`；读写在 `asyncio.wait_for(timeout=config.agent_memory_timeout_seconds)` 内完成；**任何异常都不得上抛影响问答主链路**。

### D5. 并发覆盖
采用「读最新画像 → 合并 → `SET key value EX ttl`（last-write-wins）」。读取必须发生在**合并前即时读**（不是注入时缓存的副本），把竞态窗口压到「两个会话同刻超窗」的极小概率；丢失后果仅「少一条要点」，不值得引入 `WATCH/MULTI` 重试或分布式锁。写入日志带 key 与长度，便于观测覆盖。

### D6. 成本
确认：非超窗 **0 次**额外 LLM 调用；超窗时 = 会话摘要（已有 1 次）+ 画像合并（新增 1 次），且复用同一段 `overflow` 消息。

### P1 AI：配置 + Redis 存储 + 单例
1. `ai-python/app/config.py`（PII 段附近）新增：`agent_memory_enabled=True`、`agent_memory_merge_enabled=True`、`agent_memory_max_chars=400`、`agent_memory_ttl_seconds=2592000`（30 天）、`agent_memory_timeout_seconds=1.0`、`redis_host="127.0.0.1"`、`redis_port=6379`、`redis_db=0`、`redis_password=""`（env 名 `LINGXI_REDIS_*`，与 Java `application.yml` 同源）。
2. 新建 `ai-python/app/agent/memory_store.py`：
```python
MEMORY_KEY_PREFIX = "lingxi:memory:profile"

class UserProfileStore:
    def __init__(self, *, client: Any = None, host=..., port=..., db=..., password="",
                 ttl_seconds=..., timeout_seconds=...) -> None: ...
    @staticmethod
    def profile_key(tenant_id: str, user_id: str) -> str | None   # user_id 空 → None；转义 ":" 
    async def get_profile(self, tenant_id: str, user_id: str) -> str
    async def save_profile(self, tenant_id: str, user_id: str, profile: str) -> bool
    async def close(self) -> None
```
`client` 可注入（离线测试用假客户端）；真实客户端用 `redis.asyncio.from_url(..., socket_connect_timeout=0.5, socket_timeout=1.0, health_check_interval=30)`。
3. `ai-python/app/runtime.py`：新增 `get_memory_store()`（`await _get("memory_store", _build_memory_store)`，工厂内函数导包、不调 `_get`），`shutdown()` 中 `await store.close()`。
4. `ai-python/pyproject.toml` 主依赖加 `redis>=5.0`；`ai-python/.env.example` 补 `LINGXI_MEMORY_*` / `LINGXI_REDIS_*`。

**验收**：Redis 不可达时 `get_profile` 返回 `""` 而非抛错；`redis-cli ping` 正常时读写可用。

1. 前置：`redis-cli ping` → PONG；`scripts/kafka-local.sh status` 正常；Java 与 Python 均 `LINGXI_KAFKA_ENABLED=true`；AI 侧临时 `LINGXI_AGENT_HISTORY_MAX_MESSAGES=2`（几轮内即可触发超窗）、`LINGXI_MEMORY_ENABLED=true`。
2. **会话 A**（tenant=`default`，user=`u1`）连发 3 条以上 → 观察 AI 日志「会话摘要已回写」与「用户长期记忆已合并」。
3. **存储核验**：`redis-cli --scan --pattern 'lingxi:memory:profile:*'` 得 `lingxi:memory:profile:default:u1`；`redis-cli get <key>` 内容**不含**手机号、不含 `[..]`；`redis-cli ttl <key>` ≈ 2592000。
4. **跨会话生效**：新建**会话 B**（同 tenant+user，不同 session_id）提问「我上次提过的偏好是什么」→ 日志出现「用户长期记忆已注入」且长度 > 0，回答体现跨会话偏好。

6. **降级演练**：`redis-cli shutdown nosave` 后重发消息 → 问答正常、仅出现画像读写失败告警、无异常上抛；重启 Redis 后再次超窗可正常写入。
